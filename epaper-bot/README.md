# লেখক ফোরাম — ই-পেপার বট 📰

**@ePaperXpress** টেলিগ্রাম-চ্যানেলের দৈনিক পত্রিকার PDF → গুগল-ড্রাইভ → সাইটের `/epaper` পেজে স্বয়ংক্রিয় প্রকাশ।

```
টেলিগ্রাম-চ্যানেল ──(GramJS)──▶ বট ──(ড্রাইভ-আপলোড+পাবলিক-লিংক)──▶ POST /api/epaper/sync ──▶ /epaper-পেজ
```

## সেটআপ (এক-বার)

```bash
cd epaper-bot
cp .env.example .env    # তারপর নিচের ৩টি ধাপ পূরণ করুন
bun install
```

### ① টেলিগ্রাম API (api_id + api_hash) — এখনো বাকি
1. https://my.telegram.org → **API development tools**
2. অ্যাপ তৈরি করে **api_id** ও **api_hash** কপি করে `.env`-এ বসান
   (ফোন-নম্বর `01859569175` আগেই দেওয়া আছে)
3. লগইন: `bun run login` → টেলিগ্রামে আসা **OTP** দিন → `.tg-session` তৈরি হবে

### ② গুগল-ড্রাইভ রিফ্রেশ-টোকেন — এখনো বাকি
- `.env`-এ ক্লায়েন্ট-আইডি/সিক্রেট আগেই দেওয়া আছে
- Google-Cloud-কনসোলে এই OAuth-ক্লায়েন্টে redirect URI **http://localhost:4288** যোগ করুন
- চালান: `bun run token` → কনসেন্ট-দিন → প্রিন্ট-হওয়া রিফ্রেশ-টোকেন `.env`-এ বসান

### ③ সাইট-সিঙ্ক টোকেন
- `.env`-এ `SITE_SYNC_TOKEN` = সাইট-সার্ভারের `EPAPER_SYNC_TOKEN` env-এর **হুবহু একই** মান
- `SITE_URL` = সাইটের ঠিকানা (লোকাল টেস্টে `http://localhost:8080`)

## চালান

```bash
bun start          # প্রোডাকশন (pm2: pm2 start "bun start" --name epaper-bot)
bun run dev        # ডেভ — ফাইল-বদলে অটো-রিস্টার্ট
```

বট প্রতি `POLL_MINUTES` (ডিফল্ট ২০) মিনিটে চ্যানেল স্ক্যান করে — আজকের নতুন PDF পেলে
ড্রাইভে আপলোড করে (যে-কেউ-পড়া-লিংক) এবং সাইটে ঠেলে দেয়। তারিখ-ভিত্তিক ডিডুপ
`.sync-state.json`-এ।

## পুরোনো সংখ্যার রেট্রো-ক্লিন ব্যাকফিল (ড্রাইভ → ক্লিন → রিপ্লেস)

session173-এর আগে ড্রাইভে যাওয়া পিডিএফগুলোতে চ্যানেলের সবুজ `t.me/ePaperXpress`
প্রমো-লেয়ার এখনো লাগানো। ব্যাকফিল সব PDF স্ক্যান করে প্রমো পেলে **হুবহু একই
ফাইল-আইডিতে** ক্লিন-ভার্সন বসিয়ে দেয় — সাইটের লিংক/DB-রো/থাম্বনেইল-আইডি কিছুই
বদলাতে হয় না, ড্রাইভ-রিভিশনে আগের-ভার্সনও থেকে যায় (reversible)। প্রমোযুক্ত
পিডিএফের থাম্বনেইলও ক্লিন-পিডিএফ-থেকে রি-রেন্ডার হয়।

```bash
bun run backfill                              # ① ড্রাই-রান — কোন PDF-এ কত প্রমো আছে শুধু রিপোর্ট
bun run backfill -- --apply                   # ② সত্যিই রিপ্লেস (সব ফাইল)
BACKFILL_LIMIT=5 bun run backfill -- --apply  #    বা ধাপে-ধাপে: প্রথম ৫টা
bun run backfill -- --apply --force           #    আগে-চিহ্নিত ফাইলও পুনঃস্ক্যান
```

- স্টেট (রিজিউম/স্কিপ): `.backfill-state.json` — একবার clean/replaced হলে আর ধরে না
- রিপোর্ট: `.qa/backfill-report-<timestamp>.json` (প্রতি-ফাইল বিস্তারিত)
- নিরাপত্তা: ড্রাই-রান ডিফল্ট · নো-প্রমো পিডিএফ বাইট-অপরিবর্তিত · ক্লিন-পিডিএফ-এর
  পাতা-সংখ্যা মূলের সমান কি না যাচাই হয় (ইন্টিগ্রিটি-গার্ড) · ৪২৯/৫xx-এ অটো-রিট্রাই
- টেলিগ্রাম-সেশন লাগে না — শুধু `.env`-এর GOOGLE_* কনফিগ
- স্কোপ-নোট: টোকেন `drive.file`-স্কোপে — এই-বট-ই যেসব ফাইল আপলোড করেছে সেগুলোই দেখা যাবে
  (ম্যানুয়ালি-আপলোড হওয়া পিডিএফ ব্যাকফিলে আসবে না)

## সাইট-পাশ (এক-বার, সার্ভারে)

- env: `EPAPER_SYNC_TOKEN=<.env-এর সেই-একই-টোকেন>`
- API: `POST /api/epaper/sync` (Bearer) · `GET /api/epaper/papers` (পাবলিক)
- রেন্ডার: `/epaper` পেজ **শূন্য-পরিবর্তন** — `daily_content(content_type='epaper')` পুনঃব্যবহৃত

## ২৪/৭ অপারেশন-রানবুক (session184 — "পুরোপুরো অটমেট")

**২০-সেপ্টেম্বর-সংখ্যা-মিসের মূল-কারণ (RCA):** বট সাধারণ `node`/`bun` প্রসেস হিসেবে স্যান্ডবক্সে
চলছিল → স্যান্ডবক্স-রিসেটে প্রসেস-মৃত + gitignored `.env`/`.tg-session`-ও মুছে গেছে।
কোড-নয় — **পরিবেশ-স্থায়িত্ব**-ই আসল-শত্রু। চতুর-স্তরের প্রতিরক্ষা:

### ① ক্র্যাশ-প্রুফ বট (src/index.ts)
- `uncaughtException`/`unhandledRejection`-হ্যান্ডলার — ধাক্কা-খাওয়া-এররে পোল-লুপ মরে না
- ড্রাইভ-টোকেন-রিফ্রেশ ৩-চেষ্টা (৪সে/১২সে-ব্যাকঅফ; `invalid_grant`-এ সরাসরি-ফেটক)
- মিনিটে `.bot-heartbeat`-বিট — keeper ঝুলন্ত-প্রসেস ধরতে পারে
- প্রতি-ফাইলে try/catch, ঢাকা-তারিখ সর্বত্র, `BACKFILL_DAYS=3` — বট-বন্ধ-থাকলে-ও ৩-দিনের-ব্যাকলগ ধরে

### ② সুপারভাইজার (ensure-bot.sh — আইডেম্পোটেন্ট)
রিপো-ক্লোন → `bun install` → ভল্ট-থেকে `.env`-রিস্টোর → বট-ডিটাচড-স্টার্ট।
exit-কোড: `0` চলছে/চালু · `2` .env-নেই · `3` প্লেসহোল্ডার-পূরণ-বাকি · `4` স্টার্ট-ব্যর্থ।

### ③ হেলথচেক (bot-keeper.sh)
প্রসেস-মৃত → পুনঃস্টার্ট · হার্টবিট >৪৫ মি → kill+restart ·
সাইট-API-প্রোব: আজকের (ঢাকা) পেপার `/api/epaper/papers`-এ আছে কি না।

### ④ সিক্রেট-ভল্ট (প্রাইভেট-গিস্ট — স্যান্ডবক্স-রিসেট-প্রুফ)
গিস্ট-আইডি `.vault-gist-id`-এ (গোপন-নয়; রিপোতেই থাকে):

```bash
# সেভ (পুনঃঅথ-সম্পন্ন-হওয়ার-পরে এক-বারই — তারপর আর-কখনো-হারাবে না):
GITHUB_TOKEN=<টোকেন-কেবল-env> bash save-env-to-gist.sh
# রিস্টোর (রিসেটের-পরে ensure-bot.sh নিজেই চেষ্টা করে; ম্যানুয়ালি):
GITHUB_TOKEN=<টোকেন-কেবল-env> bash restore-env-from-gist.sh
```

- গিস্ট: `010a2b3bb656ac81f933678c2c8ed99f`

### পুনঃঅথ-চেকলিস্ট (সিক্রেট-হারালে — এখন ভল্ট-থাকায় আর-হারাবে-না)
1. `.env`-এ ইউজারের কাছ-থেকে: `TG_API_HASH` (+ `TG_2FA` যদি চালু), `GOOGLE_CLIENT_ID/SECRET`, `SITE_SYNC_TOKEN`
2. `TG_OTP-প্রবাহ: bun run login-send` → ইউজার OTP → `TG_OTP=… bun run src/login-verify.ts`
3. কনসেন্ট: `bun run token` → ইউজার Allow → ফেরত-URL → `bun run token "<url>"`
4. `bun run test-drive` → `bash ensure-bot.sh` → `bash bot-keeper.sh`
5. **`GITHUB_TOKEN=… bash save-env-to-gist.sh` — এই-ধাপ-ভুললে-সব-আবার-হারাবে!**
